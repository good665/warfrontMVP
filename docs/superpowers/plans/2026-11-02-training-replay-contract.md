## Server APIs (Task4; JSON fields exact)

- POST `/v1/training/runs` body `{}`. Response `{run_id,season_id,game,rules_version:int2,seed:int,starts_at,expires_at,server_now}`. Seed stable per-season, e.g. SHA256 first32bits masked positive (zero→1), persisted with rule version/game/time bounds in season row. A retry returns the same owner's unexpired active run DTO instead of trapping a lost-response client with409; it does not create or credit another run. Returned server_now lets the client derive the true remaining expiry using monotonic time even when recovering an older run.
- POST `/v1/training/runs/{id}/finish` body `{total_ticks,events:[TrainingInput...]}`. Response `{run_id,season_id,game,rules_version,score,metrics:<replay result>,verified:true,duplicate:bool,player:<existing PlayerResponse>}`. Same-body retry returns prior score/metrics after expiry too; player is a fresh DB projection so an old stored finish snapshot cannot undo later reward credit in the UI. Different body for finished run conflicts. Validate ownership first.
- POST `/v1/training/runs/{id}/cancel` body `{}` → `{run_id,status}`. Idempotent; do not undo finished records. One active run/account, expired run released. Starts limited20/min/account. Strict integer payloads and max512KiB route input; max4501actions.
- GET `/v1/training/leaderboard?season_id=YYYY-Www` (default current) response `{season_id,game,rules_version,starts_at,ends_at,settles_at,claim_until,state,entries:[{rank,display_name,score,is_me}],my_rank,my_score,participants,expected_reward}`. Unranked my_rank0,my_score0. Top50; zero score not participant; shared ranks1,1,3. State open/settling/final/expired relates to input window and claim window; rank remains readable after claim expiry.
- GET `/v1/training/rewards` → `{items:[{season_id,game,rank,score,reward,state,settles_at,claim_until,claimed}]}` for recent relevant seasons (claimable/recent4weeks plus current preview if helpful). No unrelated empty seasons needed. Current reward is preview only.
- POST `/v1/training/rewards/{season_id}/claim` body`{}` → `{reward,already_claimed,player}`. Retry returns reward0/already_claimedtrue. Final rewards30/20/10/3 by shared rank. Strict server-owned settlement and28day expiry.
- Session expires at min(start+10min,seasonend+10min), ended season settles end+10min, claims available until settle+28days (deadline exclusive). Start only current game/rules. Server elapsed>=played_ticks/100 for finish.
- Finish and claim serialize on season row and account row in consistent order. PostgreSQL FOR UPDATE and SQLite immediate write transaction; capture/check current time after acquiring relevant locks, so an in-flight finish cannot be invisible to claimed final rank. Unique best(player,season), claim(player,season), one active run/player; atomic diamond SQL increment and claim insert same transaction. No stamina/rating change.
- Canonical telemetry `match_start`/`match_complete`, modes range/drone/cipher, run_id from server. Existing safe_record_event after canonical commit; source client practice only when actual fallback local practice.
- Register new models/tables with app. `apply_growth_schema.py` must create new tables/indexes on populated DB without Player/Match loss, support explicit backup/restore tests and AUTO_CREATE_TABLES=false. Include Task1 ExperienceState2nullable timestamp+2censorbool fields (feature newly introduced, no Player edits).
