# MMO API contract v1

All routes bearer-authenticated using existing player identity, prefix `/v1/mmo`. JSON field names below are fixed for Unity JsonUtility. No secrets in logs.

- GET `/profile` -> Profile
- POST `/enter` `{zone:"frontier"|"minefield"|"ruins",role:0|1|2}` -> Snapshot. Re-entry must not reset HP/cooldowns or duplicate rewards.
- GET `/state` -> Snapshot; 409 `mmo_not_in_world` if not entered.
- POST `/input` `{sequence:int,move_x:float,move_y:float,aim_x:float,aim_y:float,attack:bool,dodge:bool,skill1:bool,skill2:bool}` -> Snapshot. Monotonic input sequence, normalized movement, finite coordinates, action cooldowns, short movement/attack TTL. Simulation advance is server time only.
- POST `/leave` `{}` -> Profile
- POST `/equip` `{item_id:string}` -> Profile
- POST `/upgrade` `{slot:"weapon"|"armor"}` -> Profile
- POST `/quest/claim` `{}` -> Profile; persistent once-only reward/next quest stage.
- POST `/party` `{action:"create"|"join"|"leave",code:string}` -> Party. Up to four members; join invite code; dungeon instance scoped to party (solo to player).

Profile: `{level:int,xp:int,xp_next:int,gold:int,role:int,weapon_rank:int,armor_rank:int,attack:float,max_hp:float,equipped_weapon:string,equipped_armor:string,quest:Quest,inventory:Item[]}`.
Quest: `{id:string,title:string,progress:int,target:int,ready:bool}`. Item: `{id:string,name:string,slot:string,power:int,rarity:int,equipped:bool}`.
Party: `{code:string,leader_id:string,members:PartyMember[]}`; solo empty code/leader and empty members. PartyMember: `{id:string,name:string,level:int,zone:string}`.
Snapshot: `{zone:string,instance_id:string,world_width:float,world_height:float,you_id:string,last_sequence:int,server_time:float,profile:Profile,players:Actor[],enemies:Enemy[],hazards:Hazard[],effects:Effect[],obstacles:Obstacle[],party:Party}`.
Actor: `{id:string,name:string,role:int,level:int,x:float,y:float,fx:float,fy:float,hp:float,max_hp:float,attack_cooldown:float,dodge_cooldown:float,skill1_cooldown:float,skill2_cooldown:float,dodge_left:float,hit_flash:float,party_code:string}`.
Enemy: `{id:string,kind:string,name:string,x:float,y:float,hp:float,max_hp:float,hit_flash:float,respawn_left:float}`. kind is `raider`, `guard`, `boss`; include dead entities only while respawning.
Hazard: `{x:float,y:float,radius:float,age:float}`; age seconds elapsed, growing danger circle is active for its displayed area. Effect: `{id:string,x:float,y:float,text:string,kind:string}`; stable unique id so clients dedup; kind `damage`, `heal`, `loot`, `level`, `quest`.
Obstacle: `{x:float,y:float,width:float,height:float}`.

Initial balance proposals: world 3600x2400; speed220, normalized directions; frontier 32-player cap; dungeon party4; XP requirements100*level, level cap50; enemy drops server-only. Input latency5Hz snapshots with 20Hz server simulation; silence stops movement/attack within~0.35sec. Dodge .3sec/3sec cooldown, grenade6sec, heal10sec. Role changes should not be exploitable for healing.

Fields can gain optional additions, but any rename/removal requires coordinating both implementers. Server implementer owns authoritative balance; communicate deviations in this document and parent message.
