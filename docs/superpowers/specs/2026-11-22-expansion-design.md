# 2026-11-22 게임 확장 설계

요청 원문: backend/docs/superpowers/specs/2026-11-22.md (17개). 사용자는 추천 순서와 추천 기본값으로 전체 구현을 승인했다.

## 접근과 순서
기존 서버 권위 RTS와 Unity Legacy 리그를 확장한다. 새 게임을 별도로 만드는 접근은 기존 자산과 서버 통합을 잃어 제외한다. 순서는 (1) 상자/아이템 (2) 점프/무기 (3) 경로/건물/차량 (4) 황금종 (5) 새 맵/성장. 각 단계는 서버 검사 후 실제 Unity 렌더 및 Play 모드로 검증한다. 구현은 서버/3D 제작/Unity 통합으로 소유 파일을 분리한다.

## 확정 기본값
- 각 기존 건물 및 저택(구역 8,9)에 도달 가능한 상자 3개. 재생성 180초. 드문 차원 상자는 외형을 구분하며 개봉 때 20%로 하늘섬 또는 지하로 진입한다.
- 풀숲/돌담 사이 도달 가능한 무작위 동전. 획득 시 자기 캐릭터 무기 1개를 기존 최대 3단계 합성 규칙으로 지급한다. 최대 단계 초과 시 가방 보관/드롭 규칙을 따른다.
- 다른 캐릭터 무기는 장착 시 그 무기의 기본 공격 외형/효과를 사용한다. 전용 무기 단계에 따라 크기, 빛, 잔상이 증가한다. 기존 자기 무기 전효과/타무기 절반 공격력 유지.
- 탱탱볼은 실내에서만 소모 가능, 조준 방향(상하/좌우/대각선)을 따라 30회 반사. 제한 전 만료되지 않도록 충분한 생명시간. 팽이는 외형 및 피해 반경 2배; 피해량 자체는 유지.
- 워프 소모품: 같은 층의 살아있는 가장 가까운 적 영웅을 안전한 전방 위치로 소환, 3초 행동불가. 대상/착지 없으면 소모하지 않는다.
- G 집결은 클라이언트와 서버에서 제거한다.
- 슈퍼점프: Shift, 기본 1칸. 장애물이면 최대 32칸 내 안전한 반대편 착지를 찾는다. 경계/막힌 착지 거부, 서버 경로 보간과 0.65초 포물선 동작, 비행 중 이동/공격/상자 이동 잠금. 판정 우회 걷기는 금지.
- 1:1 미니언은 중앙/가로 외곽/세로 외곽 3개 차선. 중앙 건물은 입구→실내 통로→출구로 통과한다. 2:2 기존 경로 유지.
- 차량은 1:1 두 저택 야외에 대칭 배치. F 승하차, 자동차 60초/적 영웅 충돌 즉사, 오토바이 120초/이속2배/실내 진입 금지, 버스는 반대 저택 야외 포탈 이동. 차량 중복 탑승 금지 및 서버 충돌 검증.
- 어느 한 팀 본진 파괴 시 즉시 종료 대신 결승 입구를 개방한다. 양 팀 영웅의 재진입/부활 경로를 보장한다. 결승 1층 로비→2층 황금종. 팀별 누적 1000 피해 먼저 달성 시 승리. 종에 가하는 모든 공격은 방어 무시 피해로 계산한다. 캐릭터끼리 전투는 유지한다.
- 맵 분기: 하늘섬→우주→외계행성, 지하→내핵→사후세계. 역방향/상대분기 우회 금지. 다음맵 포탈은 명시적 F 상호작용, 돌아갈 출구는 본 경기 야외. 각 신규 맵 플레이 크기는 기존128x128칸.
- 새 맵 최초 진입 시 총 슬롯 11개(추가 슬롯은 - 키 및 클릭), 성장 +1. 맵 진행/해당 지역 보상으로 최대10단계. 경기 내 성장만 유지. 단계당 기본 공격/방어/최대체력 +5%, 속도는 +1%(최대10%)로 기본안. 관절을 망가뜨리는 뼈 확대 대신 팔다리 장식→캐릭터별 상징 장식→몸 실루엣→무기 광채를 누적한다.
- 상승 전환은 지반 상승/등장 섬광/착지, 하강은 갈라지는 지반/낙하. 1.5초 서버 행동 잠금. 모션은 순수 시각 효과이며 서버 좌표를 직접 바꾸지 않는다.

## 외부 자산
Cathedral — Studio Lab와 The Upper Vestibule — Hallwyl Museum 원본을 우선 조사/도입한다. 다운로드 권한/원본 사용 조건을 확인하고 출처를 보존한다. 원본 접근 불가 시 원본을 도입했다고 주장하지 않고, 플레이 가능한 자체 대체 건물은 별도로 표시한다. 사용자에게 필요한 접근이 생겨도 나머지 독립 구현은 계속한다.

## 네트워크 계약
서버는 기존 fields를 유지하고 추가한다. 공통 약속:
- MmoActor/MmoEnemy: visual_character(장착 무기 기본공격 캐릭터), weapon_tier, growth_stage, jump_from_x/y, jump_to_x/y, jump_duration, transition_kind, transition_left, vehicle_kind, vehicle_left.
- MmoSnapshot: coins[{id,x,y,floor,ready}], vehicles[{id,kind,x,y,floor,rider_id}], realm_portals[{id,x,y,floor,to_floor,kind,locked}], objectives[{id,kind,x,y,floor,hp,max_hp,team}], expansion {phase,bell_damage:[float,float],bell_target:1000}.
- SquadInput: interact(bool), item/drop 최대10. battle: inventory_slots,growth_stage,region_name.
- SquadMap: 기존 interiors와 함께 regions[{floor,kind,name,x,y,width,height}]. 새 region은 서버 bounds와 동일한 크기/좌표를 사용한다.
- 기존 MmoEffect shot.character는 실제 장착 무기 캐릭터, shot.radius 기존 판정 사거리, 추가 weapon_tier/owner_id 가능. 캐릭터 기본기 판정 변경 여부는 기존 규칙 보존을 기본으로 한다.

## 검증과 보존
기존 씬/스킨/서버 기능을 보존하며 활성 Unity Assets만 수정. 수정 전 백업. 백엔드는 각 단계 회귀 검사와 전체 pytest. Unity는 DTO 호환, 11슬롯/입력, 새 지역/차량/종/동전/상자/성장/점프 렌더와 Play 모드 검증. 다운로드/외부배포/기기빌드는 별도 검증 여부를 명시한다.
