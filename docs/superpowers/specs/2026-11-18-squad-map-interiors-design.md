# 분대전 맵: 골목 + 들어갈 수 있는 건물 설계

날짜: 2026-11-18 · 대상: 1:1 / 2:2 분대전(Squad, `rts_game.py`)

## 의도와 이유

분대전 맵이 128×128 평지 잔디판이라 단조롭다. Twinsen(LBA2)처럼 **탐험하는 재미**와
**골목에서 벌어지는 전투**를 넣는다. 원작 맵 데이터·에셋은 쓰지 않고, 분위기만 참고한 오리지널 맵을 만든다.

## 목표

- 바깥 맵에 건물·물길로 골목과 광장을 만든다. 벽은 이동과 원거리 공격을 막는다.
- 건물 문으로 들어가면 별도 실내 공간(별도 층)으로 전환된다. **영웅만** 들어갈 수 있다.
- 실내는 좁은 복도·방 구조이며 보급 상자가 있다(탐험 보상).
- 일부 건물은 문이 두 개여서 맵 반대편으로 빠지는 지름길 역할을 한다.
- 1:1, 2:2 모두 공정한 대칭 맵.

## 비목표

- 일반 유닛·미니언 웨이브의 실내 진입
- 다층 건물(2층), 파괴 가능한 벽
- 무작위 맵 생성, 맵 에디터
- LBA2 파일(`.ILE/.OBL/.HQR`) 파싱이나 원작 맵 재현

## 반목표 (돌아가도 실패인 것)

- 유닛이 벽에 끼어 멈추거나, 웨이브가 본진에 도달하지 못함
- 한쪽 팀에 유리한 지형
- 영웅이 실내에 있는 동안 본진이 공격받는 걸 알 수 없음

## 제약

- 서버가 권위(이동·충돌·피해 모두 서버 판정). 클라이언트는 그리기만 한다.
  클라이언트 이동 예측이 없으므로(`FogActorVisibility.cs` 확인) 충돌 처리는 서버에만 둔다.
- 좌표계: 1칸 = 50 서버 단위 = Unity 1 단위 (`rts_map.py`). 맵 128×128칸.
- 기존 `floor` 필드를 그대로 쓴다: 바깥 = 1, 실내 = 2 이상.
  서버 `rts_combat.py`는 이미 다른 층 사이 피해를 막고, 클라이언트 `MinimapFog`/`WorldFogVisibility`/`RememberedBuildings`는 층으로 걸러낸다.
- 컴퓨터 대전(`bot_input`)과 기존 백엔드 테스트가 계속 통과해야 한다.
- Unity 코드는 `C:\Users\good6\WarfrontMVP\Assets\script\`에만 작성한다.

## 검토한 방식

| 방식 | 내용 | 장단점 |
|---|---|---|
| A. 한 장의 맵 + 투명해지는 지붕 | 실내가 바깥 맵의 일부 | 가장 단순. 별도 공간에 들어가는 원작 느낌은 약함 |
| **B. 별도 실내 공간 (선택)** | 문 = 층 전환 | 원작 느낌이 가장 큼. 기존 `floor` 체계 덕에 비용이 예상보다 작음 |
| C. 무작위 맵 | 판마다 새 맵 | 공정성 맞추기 어려움. 나중 과제 |

사용자가 B를 선택했다. 진입 대상은 **영웅만**으로 정했다(사용자 결정).

## 설계

### 1. 맵 데이터 (서버 단일 원천)

`backend/app/rts_map.py`에 정적 데이터를 둔다.

- **바깥 맵**: 한 사분면(64×64칸)을 직사각형 목록으로 정의하고, 코드로 좌우·상하 대칭 복제한다.
  두 축 대칭이어야 1:1(대각 본진 `STARTS[0]`↔`[1]`)과 2:2(팀0 = 왼쪽 두 본진, 팀1 = 오른쪽 두 본진)에서 모두 공정하다.
  - 지형 종류: `wall`(건물 몸체, 통행 불가), `water`(물길, 통행 불가), `bridge`/`road`(통행 가능, 그리기만 다름).
  - 본진 주변 반경 약 8칸, 맵 정중앙 광장(웨이브 경유지 `EXTENT/2`)과 본진→중앙→적 본진 경로는 반드시 열어 둔다.
- **건물 6채** (실내 레이아웃은 2종류만 디자인):
  - 사분면 집 4채(대칭 복제, 같은 실내): 문 1개, 실내에 보급 상자.
  - 지름길 건물 2채: 맵 위쪽·아래쪽 중앙선(`x = EXTENT/2`)에 걸쳐 있고, 서쪽·동쪽에 문이 하나씩 있다. 양 팀 진영을 잇는 숨은 통로.
- **실내 레이아웃**: ASCII 문자열 격자(`#` 벽, `.` 바닥, `D` 문, `C` 상자). 실내마다 고유 floor 번호(2~7)를 가진다.
  실내는 바깥 판(0..6400) **밖의 빈 좌표**(x ≥ 6800)에 배치한다. 클라이언트 `BeginField`는 맵 키가 바뀌면
  전장을 통째로 다시 만들기 때문에, 같은 좌표에 겹쳐 두면 층이 바뀔 때마다 재구성이 일어난다. 밖에 두면 카메라가 영웅을 따라가기만 하면 된다.
- 층별 **통행 불가 칸 집합**과 **경계 범위**를 미리 계산한다(바깥은 `35..EXTENT-35`, 실내는 해당 격자 크기).

### 2. 이동과 충돌 (`rts_game.py`, `rts_spacing.py`)

- `move()`: 기존 `max(35, min(EXTENT-35, …))` 클램프를 층별 경계로 바꾼다.
  다음 위치가 통행 불가 칸이면 x만, 그다음 y만 이동해 본다(벽을 따라 미끄러짐). 둘 다 막히면 멈춘다.
  WASD 직접 이동과 회피(`dodge`)도 이 경로를 그대로 탄다.
- 길찾기: 층별 격자에서 A*(8방향, 대각선 모서리 통과 금지). 128×128이라 명령 시 1회 계산하면 충분하다.
  - `input()`의 `move/attack_move/retreat/gather` 명령 시점에 경로를 계산해 유닛에 `_path`(칸 중심 웨이포인트)로 저장하고, `command_tick`이 따라간다.
  - 웨이브 경로(`set_wave_route`)는 기존 4개 웨이포인트 사이를 A*로 이어 붙인다.
  - 목표가 막힌 칸이면 가장 가까운 열린 칸으로 보정한다.
  - `attack_move`/`focus`로 움직이는 대상 추적: 대상과 시야선이 열려 있으면 직진하고, 막혀 있으면 0.5초마다 재계산한다.
- `separate_units()`: 밀어낸 결과가 통행 불가 칸이면 그 밀기는 버린다.
- 영웅의 `avoid_heroes` 접선 회피도 막힌 칸으로 향하면 원래 방향을 유지한다.

### 3. 문과 층 전환

- 문은 `(층, 칸) → (목적 층, 도착 좌표, 바라볼 방향)` 연결 쌍이다. 실내 `D` 칸마다 바깥 문 하나가 짝지어진다.
  지름길 건물은 실내 `D` 두 개가 서로 다른 바깥 문에 연결된다.
- **영웅**이 문 칸에 들어서면 `floor`와 좌표를 즉시 바꾼다. 같은 문으로 바로 되돌아가지 않도록 1초 재진입 대기를 둔다.
- 영웅이 아닌 유닛에게 문 칸은 그냥 통행 불가 칸이다.
- 바깥에서 건물 위를 클릭해 영웅에게 이동 명령을 내리면 가장 가까운 문을 목표로 삼는다.
- 영웅이 죽으면 기존대로 본진(floor 1)에서 부활한다.

### 4. 시야선과 전투

- 공용 판정 `can_hit(a, b)` = 같은 층 + 거리 + 시야선(격자 위 선분이 통행 불가 칸을 지나지 않음).
  `water`는 시야를 막지 않고, `wall`만 막는다.
- 적용 대상: 영웅 기본 공격 대상 선택, 유닛 `command_tick` 공격, 웨이브 적 탐지, 본진 포탑.
- 스킬 범위 효과(`rts_combat.py`의 반경 효과)는 층만 검사하고 시야선은 넣지 않는다(빌더 판단으로 넣어도 됨).

### 5. 보급 상자 (탐험)

- 실내 `C` 칸. 영웅이 닿으면 열린다. 영웅마다 받는 게 아니라 상자당 1회이고, 60초 뒤 다시 생긴다.
- 보상은 무작위 하나: 체력 전부 회복 / 이동 속도 증가 20초(기존 `speed_left` 사용) / 공격력 +30% 30초.
  기존 `stats()` 계산에 공격 버프 필드 하나를 추가한다.
- 상자를 열면 `effects`에 이벤트를 넣어 클라이언트가 연출한다. 상대 팀에게는 보이지 않는다(다른 층).

### 6. 스냅샷과 맵 전달

- 스냅샷의 `floor`는 그 플레이어 영웅의 층으로 한다(지금은 1 고정).
- 정적 맵(바깥 지형 직사각형, 건물, 문, 실내 격자)은 매 틱 보내지 않는다. 매치마다 한 번 받는다
  (`battle_snapshot`에 버전 키를 넣고 별도 `GET` 엔드포인트로 받거나, 매치 시작 응답에 포함. 방식은 빌더 선택).
- 상자 상태(열림/남은 시간)는 해당 층을 보는 플레이어 스냅샷에만 포함한다.

### 7. Unity 클라이언트

- `RtsBoard()`: 받은 맵으로 바깥 지형을 만든다(잔디·길·물·다리 재질을 칸 단위 메쉬 색으로, 건물은 기존 `Model()` 키트의 집·벽 모델).
  Twinsen 분위기를 위해 광장, 가로등, 다리, 울타리 같은 장식을 둔다. 장식은 통행 불가 칸 안이나 길 가장자리에만 둔다.
- 실내 형상(바닥, 벽, 문, 상자)은 판 밖 좌표에 한 번만 만든다. 카메라는 영웅을 따라가므로 따로 전환할 필요가 없다.
- **보는 층**: 기본은 내 영웅의 층. 영웅이 실내에 있을 때 **Tab**을 누르면 바깥 보기로 전환한다
  (카메라가 내 본진을 비춘다). 이 상태에서 **G**(기존 집결 명령)를 누르면 화면 중앙에 집결 지점이 찍힌다.
  현재 클라이언트에는 마우스 유닛 선택 모드가 꺼져 있다(`RtsBattleView.cs`의 `rtsFirstPerson` 고정). 그래서 지휘는 G 집결만 지원한다.
  클라이언트의 `mmoWorld.floor` 필터는 이 "보는 층" 값을 쓴다.
- 아군도 보는 층이 아니면 숨긴다(지금은 적만 층으로 걸러진다).
- 영웅이 실내에 있는 동안 바깥 본진이나 유닛이 피해를 받으면 화면 상단에 경고를 띄운다(눌러서 바깥 보기로 전환).
- 문 근처에 진입 표시, 층 전환 시 짧은 페이드.
