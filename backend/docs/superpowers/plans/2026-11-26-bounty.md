# 연속 처치 현상금 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 적 영웅을 2연속 처치한 영웅에게 현상금을 걸고, 그 영웅을 적 영웅이 잡으면 장비 한 개를 떨구고 추가 경험치를 준다.

**Architecture:** 서버 `RtsCombat.award_kill`에서 연속 처치를 세고 현상금을 처리한다. 장비 드롭은 기존 바닥 아이템 `place`, 알림은 기존 `notify`를 쓴다. Unity는 "현상금" 알림을 맵 상단 작은 띠로 보낸다.

**Tech Stack:** Python 3.10 FastAPI 백엔드(pytest), Unity 6000.3 C# (IMGUI HUD).

**Spec:** `backend/docs/superpowers/specs/2026-11-26-bounty-design.md`

## Global Constraints

- 현상금 기준: 죽지 않고 적 **영웅** 처치 **2연속**부터. 어시스트·미니언 처치는 세지 않는다.
- 어떤 원인으로든 죽으면 연속 처치 0.
- 추가 경험치: 기본 영웅 처치 100(`XP['hero']`) + 연속 처치 1회당 50.
- 떨어지는 장비: 장착 무기(slot 0)·갑옷(slot 1) 중 `tier()`가 높은 것, 같으면 무기. 겹친 장비는 한 개만.
- 영웅이 아닌 원인(미니언·본진)으로 죽으면 장비를 떨구지 않는다.
- 알림은 `notify(h, text, False)`, Unity에서는 맵 상단 작은 띠.

## Review Focus

- 현상금 영웅이 미니언에게 죽음 → 연속 처치 0, 장비 그대로, 경험치 없음. (Task 1 `test_minion_kill_resets_streak_without_drop`)
- 잡은 영웅이 최대 레벨 → 경험치는 버려져도 장비는 떨어져야 함. (Task 1 `test_max_level_killer_still_makes_gear_drop`)
- 금 등급 무기 9개 → 8개 남고 한 개(`weapon_x`)만 바닥에. (Task 1 `test_stacked_gear_drops_one_copy`)
- 현상금 영웅을 잡은 영웅도 자기 연속 처치가 올라 바로 현상금이 붙을 수 있음. (Task 1 `test_claiming_counts_toward_own_streak`)
- 2대2 어시스트는 연속 처치로 세지 않음. (Task 1 `test_assist_does_not_count`)
