# 우선순위 전체 개선 결과

요청한 순서대로 모든 구현을 마친 뒤 마지막 단계에서 테스트·화면·연동 검사를 진행했다. 기존 수동 타깃 고정을 유지하며 나머지 2~6번을 연결했다.

## 구현

1. 수동 타깃 고정: 기존 Tab/화면 버튼 유지. 버튼 배치 설정과 새 전투 화면에 연결.
2. 공격 예고·피격 반응: 일반 적 0.7초/보스 1초의 고정 위치 공격 예고, 범위·진행 표시, 서버 판정 후 피해·회피, 피격 경직·강조·처치 동작·타격음. 장면 전체를 정지시키지 않는다.
3. 임무 다양화: 기존 누적 처치 임무 보존 후 일반 처치→정예 경비병→지점 탐색→유적 보스 순환. 서버가 판정하고 SQL에 진행과 보상을 저장. 임무 창에서 설명·진행·보상·목표 지역·추적/수령 제공.
4. 장비 비교: 무기의 공격력, 방어구의 최대 HP를 현재 장비와 비교해 예상 값과 증감 표시. 새 장비 획득 알림은 최초 접속을 제외하고 아이템 ID로 중복 방지.
5. 미니맵·길찾기: 자신과 방향, 적, 동지역 파티원, 서버 장애물, 실제 임무 목표 지점 표시. 목표 방위·거리 안내와 유적 입장 버튼 제공. 존재하지 않는 입구 좌표는 만들지 않음.
6. 조작 설정: 마우스/터치 감도, 상하 반전, 기본 카메라 거리, 타격음 켜기/음량. 이동/타깃/공격/회피/두 스킬 각각의 크기·좌표 미리보기와 저장/취소/기본값 복원. 겹침 저장 차단·화면 밖 배치 제한. 실제 입력도 같은 사각형을 사용.

## 검사 결과

- 백엔드 전체 `python -m pytest`: **191 passed**, 40.22초.
- `checks.log`: 설정 손상 복구·취소/저장/재로딩·버튼 겹침·감도/상하 반전·장비 비교·획득 알림 중복·임무 목표/지도 좌표·서버 예고 지오메트리·피격 효과 검사 통과. 기존 TargetLock/ThirdPerson 및 연결된 리그·성장·UI·애니메이션 검사 통과.
- `play-mode.log`: 실제 Game 뷰 6개 화면 캡처 및 Input System Tab 이벤트 검사 통과. 스크린샷: `hud.png`, `scene.png`, `equipment.png`, `quests.png`, `camera-settings.png`, `touch-settings.png`.
- `http.json`: 실제 로컬 FastAPI→PostgreSQL에서 새 임무/예고 계약, 보상 저장과 중복 수령 거절 확인. 검증용 계정은 정리했다.
- `unity-http.log`: 실제 Unity ApiClient→FastAPI→PostgreSQL→MmoApply→3D 장면 생성 경로와 서버 이동·장비 응답을 확인했다. 이 검사에 사용한 별도 계정도 정리했다.
- `migration.json`: 로컬 개발 PostgreSQL을 pg_dump로 백업한 뒤 nullable `quest_state` 컬럼 추가. 기존 캐릭터 1개의 처치 수·임무 단계·골드를 보존했다. 전체 덤프는 비공개 `.tools/all-improvements/`에 보관.
- 독립 코드 검토에서 발견한 설정 슬라이더 뒤 입장 버튼의 입력 가로채기를 수정했다. 화면 검사에서 공격 예고와 적 이름 겹침도 수정한 후 Unity 검사를 재실행했다.
- `installed.json`: 검증한 Unity 파일 10개를 활성 `C:/Users/good6/WarfrontMVP/Assets`에 백업·원본 해시 확인 후 적용했다. 기존 씬과 `.meta`는 유지했다.

## 사용

- 마을 상단 `조작 · 소리 설정`, 전투 상단 `조작 설정`에서 설정.
- `캐릭터`에서 임무 내용과 보상 확인. `장비`에서 장착 전후 수치 확인.
- 미니맵 흰색은 자신, 청록은 파티원, 빨강은 적, 금색은 추적 목표.
- 예고 범위를 벗어나거나 Shift/회피로 피한다. 창을 열어도 온라인 전투는 계속 진행된다.

## 적용 범위와 한계

로컬 개발 서버와 활성 Unity Assets에 적용했다. 외부 운영 배포·신규 APK 빌드·모바일 실기기 검사는 수행하지 않았다. 마지막 UI는 독립 Unity 검증 프로젝트의 실제 Play Mode에서 확인했다. 활성 편집기는 최소화되어 UI 자동 접근이 거절되었으므로, 기존 실행 중 Play 세션에서의 최종 재확인은 별도로 수행하지 못했다. 활성 Unity를 복원하고 Play를 정지 후 재실행하면 변경 코드를 가져온다.
