# 릴리스 노트 작성

## 단계
1. 최근 태그 이후의 커밋 목록을 확인한다 (git log).
2. 변경을 카테고리로 분류한다: 새 기능 / 버그 수정 / 개선 / 문서.
3. 사용자 관점의 문장으로 다시 쓴다(내부 용어 지양).
4. 아래 형식으로 출력한다.

## 출력 형식
## vX.Y.Z (YYYY-MM-DD)
### 새 기능
- ...
### 버그 수정
- ...

## 규칙
- 사용자에게 의미 없는 변경(내부 리팩터링 등)은 생략하거나 묶는다.
- 한국어로, 간결하게.
